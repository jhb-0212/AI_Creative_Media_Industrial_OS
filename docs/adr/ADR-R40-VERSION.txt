ADR-R40 版本索引（append-only，只追加不修改）
================================================================================
用途
--------------------------------------------------------------------------------
本文件是 ADR-R40 的唯一版本指认处。设计意图：把「版本指纹」从正文里拿出来，
避免「改了正文 → 正文里写的哈希失效 → 没人知道哪份是真的」这一类自相矛盾。

规则（三条，不可协商）
--------------------------------------------------------------------------------
R1  只追加。任何一行一旦写入，不得修改、不得删除。发现记错，只能追加一行
    「CORRECTION」更正行，写明被更正的行号与原因。
R2  正文不内嵌自身哈希。ADR 正文只写「指纹见本文件」，因为正文一变哈希即失效。
R3  哈希必须带口径。每个摘要值必须注明取字节方式：
      - git blob SHA1：git 对仓库内字节计算（受 core.autocrlf 影响，取决于提交时的存储形态）
      - 文件 SHA-256：工作区磁盘字节（Windows 上可能是 CRLF）
    两者不得混用，也不得只给其中一个而不说明是哪个。
    历史教训：v1.4.2 附录 C.1 六行中有两行按 CRLF 算出、四行按 LF 算出，任何人复核都会
    「对不上」，且无法分辨是文档错还是文件被改——这是本轮定版必须先解决的口径问题。

「现行有效」= 复审、实现、验收应引用的版本。v1.4.2 保留的唯一目的是逐版对照，

复核命令（任何人可逐字复算）
--------------------------------------------------------------------------------
  cd <repo>
  for f in docs/adr/ADR-R40-unified-authorization-model.md \
           docs/adr/ADR-R40-unified-authorization-model.v1.4.3.md; do
    printf '%s\n  sha256=%s\n  blob  =%s\n  lines =%s\n  bytes =%s\n' "$f" \
      "$(sha256sum "$f" | cut -d' ' -f1)" \
      "$(git hash-object "$f")" \
      "$(wc -l < "$f")" \
      "$(wc -c < "$f")"
  done

  判据：四个值必须与本文件对应条目逐字相同。任一不同即视为「被改动或取字节方式不同」，
  不得以「大概一致」放过；先确认是 CRLF/LF 差异还是内容差异（见 R3）。

已知缺口（不掩盖）
--------------------------------------------------------------------------------
G1  两个 ADR 文件都**未被 git 跟踪**（git ls-files 无输出）。因此 git_blob_sha1 只是
    「当前工作区字节」的哈希，没有 commit 作为外部锚点——无法证明某个提交里就是这份内容。
    定版不等于可追溯；要真正不可篡改，必须把这两个文件纳入版本控制并打 commit/tag。
    本文件如实记录该缺口，不声称「已冻结不可变」。
G2  v1.4.3 的「定版」仅指**文本冻结**：不含批准、不含发布、不放宽任何 DP/IP 判定。
    阶段 3 依旧被阻塞（见 ADR §8 与附录 I）。
G3  本文件自身不登记自身哈希（同 R2 的理由）；它以追加方式演进，历史条目不可回改。
