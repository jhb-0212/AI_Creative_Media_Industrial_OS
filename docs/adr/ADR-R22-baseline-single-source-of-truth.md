# ADR-R22：基线正文的单一事实源与「游离副本」闸门

- 状态：已实施（2026-11-18）
- 关联：N-01、ADR-R15（契约冻结生命周期）、ADR-R11（不可变性与授权基线）
- 取代：`README.md` / `docs/architecture/repository-structure.md` 中对根目录基线副本的指称
- 上游依据：`docs/audits/2026-11-18-full-repo-baseline-and-root-cause-audit.md` §7 N-01

## 1. 问题不是「文件放错位置」

根目录长期存在一份**未纳管**的基线正文副本 `AI影视工业化生产平台V2.0.5.md`（untracked，5107 行，
CRLF，SHA-256 `d71d71e8…`），与受校验的 `docs/baseline/` 那份（5095 行，LF，`9a9940c5…`）实质不同。
`README.md:5` 把它称作「配套基线文档」，`repository-structure.md:5` 直接引用它的文件名。

如果只是「多了一个文件」，删掉即可。真正的问题是：**「基线」这个词在仓库里失去了确定性**——
读者按 README 找到的正文，不是闸门校验的那份；而 CI 全程绿灯，因为 `freeze_manifest` 只认固定路径。

这与 P1-05（闸门只能证明「有人写了 satisfied」）是同一形态的第二次出现：
**校验的对象不是人实际读的对象**。

## 2. 副本里到底改了什么（差异已逐行归档）

归一化换行后差异仅 4 个 hunk / +15 / −3 行。全文归档于
`docs/audits/2026-11-18-stray-baseline-copy-drift.md`，此处只给结论：

| # | 改动 | 性质 |
| --- | --- | --- |
| 1 | 架构树新增 `services/shot-planning/`、`services/generation-execution/` | **未裁定的设计主张**（两个服务域都不存在） |
| 2 | 数据所有权表拆出 `Shot Planning` 行、新增 `Generation Execution` 行 | **未裁定的设计主张**（Intent 按作用域拆两半是全新主张） |
| 3 | 31.6「当前共注册 **75** 项」改为「**83** 项」并追加 8 行 action | **手工回填已批准修订**（A1 的 6 条 + A2 的 2 条，一字不差） |
| 4 | 两处引用「作用域拆分见 `ADR-R27 §3.5`」 | **悬空引用**（`docs/adr/` 只到 R21，该 ADR 从未存在） |

第 3 条最能说明问题：`75 + A1(6) + A2(2) + A3(1) = 84`，真实注册表就是 84，
副本回填到 A2 就停手、数了自己加的行写下 83——**A3 的 `ASSET.STATUS.CHANGE` 被漏掉**。

这不是破坏，是一次「想让正文看起来完整」的手工回填。它的价值在于证明缺口在流程而不在人：
**正文回填这条路既没有入口定义、也没有校验，所以做对和做错都看不出来。**

## 3. 根因（三条，缺一不可）

1. **校验只认固定路径**：`check_baseline_document()` 读 `BASELINE_DOC` 常量指向的那一个文件，
   对「仓库里还有第二份同名正文」完全无感。
2. **文档层给副本背书**：README 用「配套基线文档」称呼它，于是副本获得了「官方认可」的外观。
   这是最恶劣的一环——它让后来者**优先相信错的那一份**。
3. **正文数量是手写副本**：31.6 那句「当前共注册 N 项」是人手维护的第二个数字。
   注册表已经用 `total_actions` 与条目数互校（`test_total_actions_field_mismatch_detected`），
   正文这一份却没人管，于是「75 / 83 / 84」三个数字并存。

## 4. 决策

### D1-a 唯一权威路径

基线正文只存在于 `docs/baseline/AI影视工业化生产平台V2.0.5.md`。仓库内**不得**出现任何同名副本。

正文需要修订时的唯一路径（沿用 ADR-R15，不新增流程）：

```
改正文 → 重新派生十一类产物 → freeze_manifest --write 重签
（若涉及新增 Action/Schema/状态机：先改 contract_amendments.yaml 登记，再派生，最后重签）
```

### D1-b 闸门：「同名即歧义」，不看内容

`scripts/freeze_manifest.py` 新增 `check_stray_baseline_copies()`，随 `--check` 执行：

- 从 `ROOT` 递归扫描（用 `os.walk`，跳过 `.git` / `.venv` / `node_modules` / 各类缓存目录）；
- 文件名按 **casefold 比对**：Windows 上 `…V2.0.5.MD` 与 `…V2.0.5.md` 本就是同一个文件，
  而 Linux CI 大小写敏感，精确匹配会让它以「另一个文件名」的身份逃过闸门；
- 命中与 `BASELINE_DOC.name` 同名的文件，且不是权威路径本身 → 报红；
- 报错文案直接给出「要么删除副本，要么改权威路径后重签」的二选一。

**为什么按文件名判而不按内容判**：内容相同也照样有问题——下一个人改的可能是没受校验的那一份，
改完 CI 依然全绿。歧义本身就是要消灭的对象，不是「分歧」才要消灭。

### D1-c 正文自述数量必须等于冻结清单

新增 `check_baseline_self_reported_counts()`：解析 31.6 的「当前共注册 N 项规范 action_key」，
要求 `N == frozen_inventory.baseline.counts.actions`（当前 75）。

**注意方向**：正文是**冻结快照**，N 描述的是快照，不是当前注册表大小（84）。
把 N 改成 84 才是错的——那样正文就成了派生文件的镜像，修订增量失去了「基线 + 增量」的可分离性。

句子不存在时不报错：删除这句话必然改变正文字节，由第一层哈希校验拦截。

### D1-d 悬空 ADR 引用：删除，不补空号

`ADR-R27 §3.5` 从未存在。处置：**不补写、不预留编号**。ADR 编号按实际签发顺序分配，
先占号后补写等于制造第二个悬空引用。

「Intent 作用域拆分」若经所有者裁定确需成文，在 D3/D10 落地时按当时的实际编号签发正式 ADR。
在此之前它以「未裁定主张」的身份存在于归档文件 §3.3，不具任何效力。

### D1-e 副本内容的处置：归档而不是抹掉

副本里那 3 条未裁定设计主张可能是有人认真想过的（尤其「镜头域拆成独立服务域」与 ADR-R18
的 Shot 独立建模方向一致）。因此**先逐行归档，再删除副本**：

- 归档：`docs/audits/2026-11-18-stray-baseline-copy-drift.md`（含 4 个 hunk 的 verbatim diff）；
- 删除：根目录副本；
- 移交：3 条主张作为 D6（30 项基线缺口分批裁定）的输入，裁定通过走修订登记，裁定否决在归档文件标注 `REJECTED` 并写理由。

## 5. 被否决的备选方案

| 方案 | 否决理由 |
| --- | --- |
| 把根目录副本设为权威 | 与 `frozen_inventory.yaml`、`contract_amendments.yaml`、`README:55`、`phase0_manifest.md` 全部冲突，改动面远大于删一个 untracked 文件；且它本身带着 83 这个错数和悬空引用 |
| 两份都保留，加「哈希同步」断言 | 同步断言只保证一致，不保证唯一——仍然没人知道哪份是源；而且会固化「正文有两个落点」这个错误模型 |
| 把副本加进 `.gitignore` | untracked 文件照样被人读、被 Agent 读；ignoring 只是让 git 看不见，等于把问题藏得更深 |
| 只改 README，不删副本 | 副本仍在，Agent 按文件名 glob 仍会找到它；这是本次事故的直接成因，不能只修指路牌 |

## 7. 验收

- `freeze_manifest --check` PASS（基线未变 / 十一类产物哈希一致 / 演进有据 84 = 75+9）；
- 删除副本**之前**先跑闸门确认报红（证明断言对真实缺陷有效，不是事后补的装饰）：

  ```
  [FAIL] 发现基线正文的游离副本：AI影视工业化生产平台V2.0.5.md；基线唯一权威路径是 docs/baseline/…
  ```

- `find . -name "AI影视工业化生产平台V2.0.5.md"` 只剩 `docs/baseline/` 一处；
- 28 条冻结包测试全绿（含 7 条新增）。

## 8. 残余风险

1. **正文回填仍无「模板」**：本 ADR 只保证「不合规的回填会被发现」，没提供「合规回填怎么做」。
   当前口径仍是「正文是冻结快照，不回填修订内容」——这是最省事的合法解，但若将来所有者要求
   正文自含完整动作表，需要一次正式的正文修订（走 ADR-R15 流程），届时「正文与注册表的一致性」
   就该由派生脚本保证，而不是人。
2. **扫描边界是可配置的**：`_SCAN_EXCLUDED_DIRS` 目前排除了 `.git/.venv/node_modules/缓存`。
   如果将来有人把正文放进别的大型目录，仍会被扫到（这是期望行为）；但若有人把副本**改名**
   （如 `AI影视工业化生产平台V2.0.5(1).md`、加后缀 `.bak`），本断言不会命中——**改名副本由文档
   评审兜底**，不为它再加一层模糊匹配（模糊匹配会误伤 `2026-11-16-review-round3-response.md`
   这类引用正文标题的合法文档）。大小写变体属同一名字，已由 casefold 比对覆盖。
3. **`docs/proposals/shot-domain-contract-closure.md` 仍有「本机未找到基线正文」的历史陈述**：
   那是提案写作时的真实状态记录，不改写历史；权威路径以本 ADR 与 README 为准。
