# ADR-R25：Release 源码包只从 commit 构建，并在写入前过密钥闸门

- 状态：Accepted（F6 处置）
- 日期：2026-11-17
- 关联：第三轮审查 F6；`docs/audits/2026-11-16-review-round3-response.md` 第六节 D 包

## 1. 背景

仓库根目录曾存在一个约 116 MB 的 `AI_Creative_Media_Industrial_OS.zip`。只读盘点结果：

| 项 | 数量 |
|---|---:|
| 归档条目 | 14,914 |
| `.git/` 条目 | 272 |
| `.venv/` 条目 | 14,172 |
| `__pycache__/` 条目 | 3,068 |
| `.env` / `.env.*` | 2 |
| `.workbuddy/` 条目 | 5 |

该包把工作目录原样压缩：既不可复现（同一源码不同本地状态产生不同包），
又把本地 `.env`、虚拟环境和缓存一并交出去。其结果是：

1. 接收方无法证明「这个 zip 对应哪个 commit」；
2. 本地凭据有真实外泄面，即使值只是开发默认值，也不应由交付物承载；
3. 包体积中的绝大多数条目与源码无关，审查成本被放大。

## 2. 决策

### 2.1 来源唯一

发布包内容**只来自** `git archive <commit>` 的受版本控制文件。

- `git status --porcelain` 默认必须为空；脏工作树需显式 `--allow-dirty`，仅用于本地排查。
- `ref` 先解析成 commit SHA，归档使用 SHA，避免构建期间 ref 漂移。
- 归档成员集合必须与 `git ls-tree -r --name-only <commit>` 完全相等；
  缺文件或多文件都失败。
- 本地 `.env`、`.venv`、缓存、`.git`、`data/local/` 从物理上不进入归档。

### 2.2 写入前双闸门

在 ZIP 落盘之前依次执行：

1. **禁止路径闸门**：按路径模式拒绝 `.env*`、虚拟环境、缓存、`.git`、密钥文件、
   日志与本地数据。`.env.example` 明确允许。
2. **密钥扫描闸门**：使用 `scripts/release_scan.py` 的规则集匹配 PEM 私钥块、
   AWS/GitHub/Slack/OpenAI token、JWT、行首长凭据赋值与 URL 内嵌密码。

命中输出**只含路径、行号、规则 ID 和 SHA-256 前 12 位指纹**，不输出命中原文。

### 2.3 误报放行必须可审计

已知测试夹具通过 `contracts/runtime/release_secret_allowlist.yaml` 放行。
每条放行必须包含 `path + rule_id + fingerprint + reason`；缺理由、指纹非法或重复条目
都会让清单加载失败。放行按精确三元组匹配，文件换了位置或规则换了 ID 都要重新登记。

不放行「看起来像密钥的通用字符串」：代码表达式、模板插值、引用字段
（`*_REF` / `*_ID` / `*_PATH` 等）在扫描层直接排除，避免 allowlist 退化成忽略清单。

### 2.4 可复现与可验证

- ZIP 成员按路径排序，时间戳固定为 1980-01-01，权限位归一化为 0644；
- 包内 `RELEASE_MANIFEST.json` 记录 schema 版本、源 ref、commit SHA、规则版本、
  allowlist 哈希和逐文件 SHA-256，不含生成时间；
- 同一 commit 的两次构建逐字节一致；
- `--verify` 独立验证包结构、禁止路径、逐文件哈希和密钥扫描；
- `--check` 构建到临时目录并验证，不留下交付包，供 CI 使用。

## 3. 拒绝的方案

- **压缩整个工作目录再删掉敏感文件**：先复制后清理，任何一步中断都会留下带密钥的包；
  且无法证明包对应哪个 commit。
- **直接复用 `.gitignore` 作为发布黑名单**：`.gitignore` 是开发期约定，不是交付契约；
  它不禁止已被误提交进 index 的文件，也不描述密钥内容。
- **只做文件名黑名单、不扫内容**：无法发现 `config.py` / 测试夹具 / 迁移脚本里的字面量凭据。
- **通用高熵扫描**：`uv.lock`、哈希清单和基线文档天然高熵，会产生大量无法裁决的噪声；
  采用「厂商 token 形态 + 严格赋值形态 + 显式放行」更可维护。

## 4. 后果

- CI 增加 `release_package --check` 闸门；发布流程使用 `--output` 生成 `dist/` 下的包。
- 开发者想从脏工作树做临时包必须显式传 `--allow-dirty`，该包仍会被扫描与验证。
- 旧 ZIP 应被视为**已暴露的本地配置样本**：其中的 `.env` 含有数据库/S3/网关等凭据键；
  任何非占位值都必须轮换，不能因「只是开发包」而豁免。
- 本 ADR 只证明源码包结构与静态密钥规则；不证明容器镜像依赖安全，
  也不替代压测与故障演练证据。这两项继续在 README「未覆盖范围」中登记。
