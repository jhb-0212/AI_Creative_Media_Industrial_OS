## 2. #34 为什么不能"补 GRANT"，只能"按父态收回"

`legacy_statements()` 的旧口径有两处根因，都是**把"我授过"当成"父态本来就有"**：

1. 默认权限对 `DOMAINS` 全量循环 → 给每个域角色在**别人的** schema 里也建
   `TABLES/SEQUENCES` 默认授权。父态只有 `asset_service_role@asset_service`、
   `project_planning_role@project_planning` 两条。
2. `converge_statements()` 在升级时给三个新域角色授了共享 schema 的 USAGE
   与共享表的 SELECT/INSERT；这些**父态不存在**，而 `legacy_statements`
   按"共享 schema 不归我管"跳过，于是留在 D 上。

修复分三层，全部以 P 为准：

- `packages/shared/db_grants.py::legacy_statements` 的默认权限只恢复**本域自己的 schema**；
- `c1a2b3d4e5f6` 降级对 `production_planning / budget_quota / qc_governance`
  三角色撤 `audit/auth/outbox/public/project_planning` 的 USAGE；
- 同三角色撤 `audit.status_transitions`、`auth.revoked_tokens`、
  `outbox.outbox_events`、`public.alembic_version` 的表级授权；并撤
  `asset_service_role / project_planning_role` 在 `public` 的 USAGE；
- 三个新域 schema 的默认权限条目用 `REVOKE ALL` 归零（父态无条目）。

## 3. #62 的探针：`GRANT` 会新建行，`REVOKE` 才会删行

在一次性探针库 `afs_t62probe` 上实测：

- 升级后 `pg_default_acl` 无 `qc_maintenance` 行（0 rows）；
- 降级后出现 `{=X/qc_maintenance_owner}` 一行（父态没有）；
- 对同一目标再执行一次 `REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC`，该行消失。

结论：`ALTER DEFAULT PRIVILEGES` 存的是"相对内置默认的差异"，降级用 `GRANT`
会写出一行差异；用 `REVOKE` 才回到"没有行"。已据此改
`maintenance_function_public_reclaim_restore_statements()`。

## 4. #41 的对象生命周期（不套用 D-02 的索引改名修法）

实测事实：

- 五张表在 P 与 D 的 **OID 全部不同**（`budget_ledger` 113463→113622、
  `gate_decisions` 113485→113634、`generation_tasks` 113442→113597 等）→ 降级**重建了表**；
- 列结构逐字相同；索引定义相同但**名称不同**
  （P：`ix_project_planning_gate_decisions_gate_key`，D：`..._project_id_gate_key`）；
- 表 ACL 从"无显式 ACL"变成 `postgres + project_planning_role=ar/arw`；
- `budget_quota / production_planning / qc_governance` 三个 schema 的 ACL 从默认变成显式。

因此 #41 不是"漏删对象"，而是 **`object_identity_or_definition_drift + ACL_drift`**。

修复：
1. `_index_name()` 对 `gate_decisions (project_id, gate_key)` 沿用父态后缀 `gate_key`——
   索引名是对象身份的一部分，不能靠"改个名字"掩盖表重建；
2. 降级重建后不再按 `legacy_r16_grant_statements` 授旧角色表权限（P 上五表就是属主默认权限）；
3. 三个新 schema 的 USAGE 在降级时收回（schema 对象保留，后续 revision 仍引用）。

数据保全：upgrade 在 cutover 处 `DROP TABLE IF EXISTS` 旧表，并在同处声明
"cutover 时点五表均为 0 行，无数据搬运"。降级重建空表**没有新增数据损失**，
这是既有的有损设计（结构性回滚，不回填 cutover 后写入新 schema 的行），
已写在 `a0b1c2d3e4f5` 的 `downgrade()` docstring 里，不再用"表名/索引名一致"冒充数据保全。
