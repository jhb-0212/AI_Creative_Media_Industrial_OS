## 1. 被测后端

| 后端 | 端点 | 实际产品 | 桶 | 证据 |
|---|---|---|---|---|
| SeaweedFS | `http://localhost:8333`（S3 gateway） | `chrislusf/seaweedfs:latest`（镜像 `4b42c212…`） | `poc-tech04-seaweedfs`（专用） | `[V-VERIFIED][E5]` |
| RustFS（作为「成熟 S3 兼容实现」一侧样本） | `http://localhost:9000` | `rustfs/rustfs:latest`（镜像 `ee717072…`） | `poc-tech04-rustfs`（专用） | `[V-VERIFIED][E5]` |

客户端：boto3/botocore **1.44.2**（现有依赖，**未新增/未改**依赖锁）。两后端均实测支持 S3 条件写入 `IfNoneMatch='*'`（重复写已存在对象返回 `412 PreconditionFailed`）——这是防覆盖能落在存储层、无需外部协调的事实依据。

**对比口径声明**：ADR ⑦ 要求对比「SeaweedFS 与成熟云 S3」。本次以 RustFS 作为成熟 S3 兼容实现一侧的样本；**AWS S3 真实服务端不在本机，未测**——见 §5 缺口。不以「API 兼容」单独判 PASS：七项含防覆盖、哈希复核、异常翻译、权限拒绝等安全语义。

## 2. 逐项取证结果

### ① 复用并审查 Port 与 locator `[V-VERIFIED][E2]`
- 候选 Adapter 满足 `ObjectStoragePort` 的 put/get/exists 三方法，无 `delete`（Port 定义本身刻意无 delete，产物生命周期归资产状态机）。
- locator 直接调用生产唯一定义 `build_locator`/`parse_locator`，返回 `local://<2>/<2>/<64hex>.<ext>`，与 LocalFS 完全同构；非法 locator（前两段与哈希不符、非登记扩展名）被拒——「语法合法但永远读不到」的拼写错误在 parse 层即挡下。

### ② 候选 Adapter put/get/exists `[V-VERIFIED][E2]`
- 实现在审计目录 `s3_adapter.py`，**未进** `adapters/`，不影响生产装配。
- 三方法齐备、无 delete；对象键布局 `<a>/<b>/<digest>.<ext>` 与 locator 一一对应；失败全部翻译为 `ports.py` 声明的异常族。

### ③ 条件写入/完整性/大小/类型 `[V-VERIFIED][E5]`
双后端各实测：
- put 返回受控 locator，sha256 与内容一致；get 字节完整读取且哈希复核通过；exists 命中。
- **防覆盖**：同内容重复 put（同一 key）被 `IfNoneMatch='*'` 挡下，抛 `StorageIntegrityError`，不静默覆盖。
- 上游声明 `expected_sha256` 不符 → 落盘前拒绝；超 `max_bytes` → 前置 `StorageSizeLimitError`；未登记 media_type（`application/x-sh`）→ `StorageLocatorError`；非法 locator 的 `exists` 返回 False 而非抛错（Port 契约）。

### ④ Multipart 中断/清理/版本策略 `[V-VERIFIED][E5]`（有限）
- 两后端均实测：创建 multipart upload → 上传 1 个 part → `list_parts` 见到 1 个 → `abort` → 再 `list_parts` 失败（upload 不存在），部分对象清理有效。
- 版本策略 `get_bucket_versioning` 两后端均返回 `Status=Unversioned`（桶未开版本控制）。这是**本地默认配置**，非后端不支持——S3 版本控制是桶级开关；PoC 未验证开启版本控制后的行为，登记为范围外（§5）。
- 未接 Multipart 重试/大对象分片的完整链路（PoC 规模小，单 part 直传已覆盖读取完整性）；登记为缺口。

### ⑤ 五类故障注入 `[V-VERIFIED][E5]`
| 故障 | 期望 | 实测 |
|---|---|---|
| 网络中断（无监听端口） | 翻译为 `S3StorageError` | PASS（初版泄漏 `ReadTimeoutError`，修正 Adapter 捕获 `BotoCoreError` 后 PASS，见 §4） |
| 权限拒绝（错误密钥） | `S3StorageError` | PASS |
| 对象缺失（合法 locator 无对象） | `StorageIntegrityError` | PASS |
| Hash 不匹配（直写篡改对象字节） | get 复核拒→`StorageIntegrityError` | PASS（绕过 `IfNoneMatch` 直写后端模拟存储篡改） |
| 服务恢复 | 换回好连接 put/get 正常 | PASS |

### ⑥ 登记前不产生正式资产引用 `[V-VERIFIED][E2+E5]`
- `ObjectStoragePort` 是 Protocol，AST 派生确认其方法体全为 stub（docstring + Ellipsis），无实现体、不落库；候选 Adapter 只返回 `StoredObject`，不写 `asset_versions`。
- 取证对象只写 `poc-tech04-*` 专用桶，与生产 `assets`/`uploads` 桶隔离； locator 从不提交资产域登记接口。

### ⑦ 双后端对比 `[V-VERIFIED][E5]`
- 两后端执行完全相同的 21 项断言集，用例集合一致、结果均为 21/21 PASS。
- 安全语义逐项通过（防覆盖/哈希/权限/异常翻译/无 delete），非仅「put/get 连通」判 PASS。
- 差异如实登记：RustFS 预置 `assets`/`uploads` 两桶（生产侧命名），SeaweedFS 初始无桶；两者版本策略均为 Unversioned（默认）。这些是配置/初始状态差异，不影响 Port 语义一致性。

## 3. 取证装置自检（证明 PASS 非假阳性）

| 检查 | 做法 | 结果 |
|---|---|---|
| 正常态 | `run_poc.py` 全量 | 42/42 PASS，`POC_RESULT PASS` |
| 变异证伪 | `TECH04_SELFTEST_MUTANT=1` 去掉 Adapter 的 `IfNoneMatch`（模拟防覆盖被移除） | 精确定位 `③ 条件写入防覆盖` FAIL（两后端各一），`POC_RESULT FAIL`，无 ERROR |

**本轮揪出的假阳性（重要）**：初版防覆盖断言用「不同内容 + 错误 expected_sha256」重复 put，哈希守卫先抛错，导致即使去掉 `IfNoneMatch` 仍显示 PASS——断言被哈希守卫掩盖，未真正测到条件写入。已改为「同内容重复 put（同一 key）」，变异态现在能报红。这是「变异点跟着被测事实走」的直接体现。

## 4. 取证中发现并修正的候选 Adapter 缺陷（E2，非生产代码）

- **BotoCoreError 泄漏**：网络中断时 boto3 抛 `ReadTimeoutError`/`ConnectTimeoutError`（`BotoCoreError` 子类，**非** `ClientError`），初版 Adapter 只 catch `ClientError`，底层异常泄漏给调用方——正是 `ports.py` 顶部声明要避免的「换后端波及所有调用方」。已在候选 Adapter 的 put/get/exists 全部补 `BotoCoreError` → `S3StorageError` 翻译。
- 注意：此缺陷在隔离 PoC 适配器中修正；若日后 S3 Adapter 正式进入 `adapters/`，必须继承这一修复。

## 5. 边界与缺口

- 取证装置在 `docs/audits/tech04-s3-poc/`，**未改** `adapters/`、`packages/`、`pyproject.toml`、Compose、冻结清单、`.env`；测试对象只在 `poc-tech04-*` 专用桶。
- 改动后 `freeze_manifest --check`、`contract_check`、`architecture_check` 全 PASS（EXIT=0）。
- **裁决 ≠ 切换**：现行生产基线仍是 `local://` LocalFS，Generation 入口对非 local 保持 fail-closed。本报告不构成切换批准；切换须 PoC 全过 + 独立 ADR 修订 + 冻结重签，且不得出现「S3 失败回落 LocalFS」。
- `[V-UNVERIFIED]` / 范围外缺口：
  - AWS S3（或成熟云 S3）真实服务端未纳入本机环境，⑦ 的「成熟 S3 一侧」以 RustFS 样本替代——若裁决门槛严格要求云 S3，需补测（登记为缺口，不伪装成已通过）。
  - 开启桶版本控制后的行为、Multipart 大对象分片重试的完整链路、长稳/容量/并发压测不在本次 PoC 范围。
