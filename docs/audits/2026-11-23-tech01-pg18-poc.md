### 3.3 条件③ catalog 逐项无回退 —— PASS `[V-VERIFIED][E5]`

判据设计（遵循「集合一律派生」铁律）：
- 用同一份只读探针 `docs/evidence/db-reconciliation/probe.sql`（11 段）分别对 PG16.15 对照库与 PG18.7 PoC 库取 catalog 快照（E5，超级用户只读，未做 DDL/DML）。
- 用 `catalog_diff.py` 按段解析、规范化空白与表头，按「行集合」对比两库，输出仅单侧存在的行；业务实体集合不等即判 FAIL。
- **剔除两项 PG18 合法版本差异**（经官方发布说明与实测确认，非回退）：
  1. `pg_constraint` 新增 `contype='n'`（NOT NULL 约束进入 catalog；PG16 仅存于 `pg_attribute.attnotnull`）——属目录表达变化，业务约束未减少；
  2. owner ACL 权限串新增 `m`（PG18 MAINTAIN 权限，`postgres=arwdDxtm` vs PG16 `postgres=arwdDxt`）——仅 owner 条目变化，**所有业务角色权限位逐一相同**（如 `asset_service_role=arw`、`project_planning_role=r` 等）。
- 结果：10 段业务 catalog（schema 清单、表/RLS/FORCE、角色、表 ACL、列 ACL、schema ACL、默认权限、RLS 策略、约束类型分布、越权扫描）规范化后**逐段完全一致，零差异**。
- **装置证伪（防假绿）**：注入一条变异（把 `asset_service.asset_versions` 的 `asset_service_role=arw` 改为 `ar`），脚本立即报 FAIL 并精确定位该行；证明装置真能报红，非空跑。
- 证据：`tech01-pg18-poc/probe-pg16-16.15.txt`、`probe-pg18-18.7.txt`、`catalog_diff.py`（可复跑：`python docs/audits/tech01-pg18-poc/catalog_diff.py` → `RESULT: PASS`）。

### 3.4 条件④ downgrade 往返 + 数据恢复演练 —— PASS `[V-VERIFIED][E5]`

**往返**：
- `alembic downgrade -1`：`e1f2a3b4c5d6 → d0e1f2a3b4c5`，EXIT=0；
- `alembic upgrade head`：`d0e1f2a3b4c5 → e1f2a3b4c5d6`，EXIT=0。
- 证明 R42 Saga 迁移（最新 revision）在 PG18 上双向可逆。

**恢复演练（逻辑 dump/restore，非数据目录挂载）**：
- `pg_dump -Fc` 源库 → 221K custom 格式转储，EXIT=0；
- 新建独立库 `ai_film_pg18_restore`，`pg_restore` 导入，EXIT=0；
- 版本一致：两库 `alembic_version` 均 `e1f2a3b4c5d6`；
- 数据一致：18 张有数据的表 `pg_stat_user_tables.n_live_tup` 逐表相同；6 张核心表用精确 `count(*)` 复核全部相等——`projects 120`、`shots 33`、`status_transitions 67`、`outbox_events 192`、`asset_versions 21`、`generation_tasks 21`。

### 3.5 条件⑤ PG18.7 发布说明注意事项处置 —— PASS `[V-VERIFIED][E1+E2+E5]`

官方发布说明取证（E1，postgresql.org 官方 Release 18 / 18.2 notes）：

| 注意事项 | 官方事实 | 本链实测 | 处置 |
|---|---|---|---|
| FTS/全文搜索改为集群默认 collation provider；非 libc（ICU/builtin）集群 `pg_upgrade` 后须 `REINDEX` FTS/`pg_trgm` 索引 | Release 18 兼容性段落 | PoC 库 `datlocprovider='c'`（libc）；业务 schema 中 FTS/GIN/GiST/trgm/ltree 索引数 = **0**（首次统计的 2 个命中均为 `pg_catalog` 系统索引，非业务索引） | **不适用**，无需 REINDEX `[V-NA]` |
| PG18.2 修复「>1GB 表在 base/incremental backup 间被 VACUUM 截断致 `pg_combinebackup` 失败」，18.7 已含修复 | Release 18.2 notes | 本 PoC 采用逻辑 `pg_dump/pg_restore`，未使用物理增量备份/组合 | **不适用**（若未来引入物理增量备份，须确保版本 ≥18.2） `[V-NA]` |
| PG18 默认启用 data checksums；MD5 密码认证弃用 | Release 18 兼容性段落 | `data_checksums=on`（正向）；`password_encryption=scram-sha-256`（不受 MD5 弃用影响） | 无负面处置 `[V-VERIFIED]` |
| `initdb` 默认 checksums 改变，`pg_upgrade` 要求源/目标 checksum 设置匹配 | Release 18 兼容性段落 | 本链用逻辑迁移，不走 `pg_upgrade` | **不适用** `[V-NA]` |

结论：PG18.7 发布说明中影响索引与增量备份的事项，对 V2.0.5 当前形态均为不适用，条件⑤ 已逐条取证并处置。`[V-VERIFIED][E1+E2+E5]`
