# 外部证据交接单（生产准入的两类外部依赖）

> **这份文档不是通过声明，而是一张任务单。** 它列的是「实现方无法自己产生、
> 必须由外部提供的输入」，以及「拿到之后按什么判据算通过」。
>
> 适用对象：模型网关提供方、目标环境负责人、独立验收方。
> 每条都写清「谁提供 / 为什么必须 / 拿到后怎么验」，缺一项就卡一项，不做推测填补。

## 零、为什么需要这份单子

生产准入清单（`production-readiness-checklist.md`）里 9 项未勾选，其中 8 项
卡在两类外部依赖上：

| 类别 | 卡住的项 | 性质 |
|---|---|---|
| 真实模型网关 | A1（全链 E2E） | 缺输入：代码侧已就绪，缺对端事实 |
| 目标环境与独立签署 | B1~B5、最终签署 | 缺主体：需要环境权限与独立验收方 |

这两类都不是「再写点代码就能过」。前者要外部给协议与凭据，后者要外部出人与环境。
把二者混为一谈，会导致「代码写完了却一直无法验收」或「验收了却没人背书」。

### 1.2 必须由外部提供的 8 项

| # | 需要什么 | 为什么必须 | 验收判据 |
|---|---|---|---|
| 1 | 网关协议文档或一份可跑的 **curl 示例** | 当前只实现 `openai_compatible`（同步 `POST /images/generations`）；**其他协议的对端都需要新适配器**，不能靠配置伪装成已支持 | 用提供的示例能拿到一份产物 |
| 2 | 从 **Worker 所在机器**可达的 `base_url` | 内网地址/需经代理，实现方网络到不了 | 在 Worker 机器上 `curl` 返回 2xx |
| 3 | 鉴权方式与凭据（API Key / Bearer / mTLS）+ 轮换方式 | 无凭据无法调用；不清楚轮换方式只能硬编码 | 凭据生效且不落日志（`repr` 与异常消息均不含） |
| 4 | 至少一个**真实可用**的 model id（或 workflow 标识） | 预算按模型计价，模型 id 是计价口径的一部分 | 一次真实生成返回非空产物 |
| 5 | 产物取回方式：URL 还是 base64、链接有效期、是否需单独鉴权 | 决定走 `_download` 还是 `_decode_b64`；有效期过短会导致下载 403 | 连续 3 次生成均成功取回 |
| 6 | 产物落地位置：S3 兼容的 `endpoint/bucket/region/凭据`，或同意先用本地受控目录 | 产物必须落到受控存储；`storage_ref` 是后续 QC 与交付的唯一定位方式 | 产物可在受控存储中按定位符读回且哈希一致 |
| 7 | 配额与速率上限、单任务超时、**单次生成成本** | 预算域的预留/结算需要成本口径；无上限会导致并发打爆配额 | 压测时报 429 能被识别为「可重试」而非「已拒绝」 |
| 8 | 输出物的**商用授权**与内容审核要求 | 影视生产必须有商用许可，这属法务事实，不能由代码假定 | 书面条款或引用条款编号 |

### 1.3 拿到之后怎么验（A1 的最小证据）

0. **先单独钉住网关这一段**：`uv run python scripts/verify_model_gateway.py --evidence runs/gateway.json`
   （配好 `MODEL_GATEWAY_BASE_URL/API_KEY/DEFAULT_MODEL` 后跑一次真实调用）。它只证明
   「协议 + 凭据 + 模型 id + 产物取回方式」成立（第一节 1–5 项），**不能**代替 A1；
   但它能把「对端不通」与「台账不通」分开，避免 A1 失败时只剩一个 FAILED。
1. 配好上述配置，确认 Worker 启动日志出现 `generation executor wired to ...`；
2. 提交一个真实生成任务，确认状态推进 `REQUESTED → RUNNING → AWAITING_ASSET_REGISTRATION`
   ——**注意终态不是 SUCCEEDED**：R42 两段式登记下，T1 只把任务推到 AWAITING，`asset_version_id`
   必须由 T2 回执经 relay 的 T3 写回后才非空（空则会被 P1-02 的产物契约降级为 FAILED）；
3. 观察 `AWAITING_ASSET_REGISTRATION → SUCCEEDED` 且 `asset_version_id` 非空，这才算 A1 的
   「链路走完」；只有步骤 1 的 SUCCEEDED 意味着拒绝把「编排跑完」当成「资产已登记」；
4. 按 `storage_ref` 读回产物，复核 sha256 与落盘时一致；
5. 保存完整日志（含时间戳、环境标识、每条断言）。**用假网关跑出来的链路
   只能证明「编排通了」，不能代替这一步。**

## 二、外部审计签署

依据 ADR-R40 §8.1，责任分离是硬约束：**IP-6 独立技术验收取证（必须独立于实现方）
→ IP-7 正式验收与签署（所有者 / 验收委员会）**。实现方不签自己的验收。

### 2.1 实现方负责产出的证据（不需要外部输入）

| 项 | 状态 | 位置 |
|---|---|---|
| D2 正式链归属验收取证 | **已出证，结论 FAIL（13/15 未通过）** | `docs/audits/mig-recon/main-chain/ownership-ledger.md` |
| A1 全链 E2E | 待真网关 + 存储 | 依赖第一节 |
| B1~B5（压测 / Redis / DB / Outbox / 备份恢复） | 待目标环境 | 依赖外部环境与故障注入权限 |

> D2 之所以「已出证但不通过」，是因为取证本身把缺口暴露出来了：5 张表
> （`shot_budget_requests` / `generation_tasks` / `production_routes` /
> `gate_decisions` / `qc_tasks`）完全没有归属路径，8 张表的 `tenant_id`
> 未被任何外键约束。这属于结构性缺陷，要补迁移，不是配置问题。

### 2.2 必须由外部提供的 5 项

| # | 需要什么 | 为什么必须 | 判据 |
|---|---|---|---|
| 1 | **独立验收方是谁**（人与组织） | 实现方自签等于没有验收；ADR-R40 要求 IP-6 独立于实现方 | 签署记录里能指明「谁、依据哪份证据」 |
| 2 | **版本锚点**：commit SHA + 迁移 head + 契约台账版本 | 签完代码又变，签署自动失效 | 三者可复算，且与签署时一致 |
| 3 | **目标环境**与故障注入权限 | B2/B3/B4 要主动制造宕机、断连；无权限则永远勾不上 | 演练报告含环境标识、注入方式、原始输出 |
| 4 | **签署形式与复审周期** | 口头通过无法复核 | 签字文档 / issue / 签名 tag 三者定一个，并定期限 |
| 5 | **责任人对应**（功能 / 目标环境 / 数据库三组） | 清单第四节已分组，但需要真实人名 | 每项都有可问责的负责人 |

### 2.3 签署前必须确认的一件事

清单里 12 项的勾选状态必须与**同一版本锚点**的证据对应。若某项证据来自
更早的 commit，签署要么限定范围，要么重新取证——不能用旧证据签新代码。

## 五、口径提醒

- **没有证据就不勾选**：配置齐了不等于跑通了，跑通了不等于环境验过了。
- **假网关不是证据**：它只能证明编排正确，不能证明模型能出片，也不能用于性能与成本结论。
- **分叉库不能替正式链**：`ai_film_industrial` 的 35/35 与正式链 `ai_film_api_tests`
  是两套谱系（三列外键 vs 两列外键 + 组织只在 projects），ADR-R41 D5 禁止互推。
- **实现方不签自己的验收**：本 agent 无签署权，也不代人签署。
- **网关返回 2xx 不等于产物内容正确**：必须按 `storage_ref` 读回并复核哈希与
  媒体类型；「任务状态是 SUCCEEDED」只证明编排跑完，不证明产物符合意图。
- **storage_ref 不是调用方可填的自由字段**（P1-07 已收敛）：形态固定为
  `local://<前2>/<次2>/<sha256>.<受控扩展名>`，由存储层 `put` 生成，且内嵌哈希
  必须等于本行 `sha256` 列。目标环境接入时若网关返回的产物需要落库，必须先
  经存储层写入拿到定位符再登记；自行拼一个 `s3://...` 会在入口被 422 拒绝。
  第 6 项外部事实里的「S3 兼容端点」因此**不是**给 `storage_ref` 填 S3 URI 的
  许可——当前只实现 local 后端，写 `s3` 存储配置会在启动时报错。
