# 事件契约（Event Catalog）——跨模块事件的唯一登记处
#
# 为什么需要它：
# - 事件名此前只活在代码字符串里，改名/改字段无人知道下游是否还在消费；
# - 更危险的是「动作登记了 audit_event，但代码从不发」——声明自洽、事实缺失，
#   这类缺口只有把事件也纳入契约才看得见。
#
# 校验规则（scripts/contract_check.py::check_event_catalog，双向）：
# 1. 代码里出现的每个 event_type 必须在本文件登记（未登记发事件 = 私自发契约）；
# 2. 本文件登记的每个 event_type 必须真被发出（陈旧条目 = 台账撒谎）；
# 3. emitted_by 必须指向真正发出该事件的文件（路径漂移报红）；
# 4. 已实现且非 READ 的 action，其 audit_event 必须已登记；确实还没落地的，
#    在 contracts/runtime/event_emission_gaps.yaml 显式登记债务，不得静默。
#
# 维护规则：
# 1. payload_required 是下游可依赖的最小字段集。删字段等于破坏契约，必须改契约；
# 2. 一个 action 可以发多条事件（例如批准要先记录「进入人工复核」）；
# 3. 事件与状态迁移同事务：不得先改状态再补事件，也不得先发事件再改状态。
