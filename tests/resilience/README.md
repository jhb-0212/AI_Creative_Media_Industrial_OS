# Resilience 测试骨架（Phase 1 生产准入缺口登记）

## 定位（先读这段，避免误读为"韧性已验收"）

本目录是第三轮工程审查 P1-2 的产物。README 明确登记 **`tests/resilience` 此前不存在**，
生产准入尚未通过。这里落地的是**故障传播契约的骨架测试**——验证「依赖故障时系统
fail-closed、异常向上冒泡、不静默吞掉」这一类**可在单机 CI 稳定复现**的行为。

**本目录不宣称已完成**报告列出的目标环境韧性验收：
- 目标并发 / 峰值 / 持续运行时长实测报告——需要目标环境，未完成；
- Redis / DB / Outbox / Worker 的真实故障演练与恢复——需要故障注入环境，未完成；
- 备份恢复、数据一致性、任务补偿的目标环境验证——未完成。

这些缺口在生产准入清单 `docs/runbooks/production-readiness-checklist.md` 中逐项登记，
未取得证据前不得勾选通过。骨架测试的 PASS 只证明"故障传播契约"这一小类，不等于韧性验收。

## 已覆盖（骨架，真实可运行、有负向路径）

- `test_failure_propagation.py`：Outbox 端口故障时异常必须冒泡，不被服务层吞成成功；
  故障不产生半提交的审计事实；失败重试不产生重复副作用（幂等）。

## 分析原则

与全仓一致：判据写明理由；fail-closed；负向测试证明闸门能 FAIL；
不把"没抛异常"当作 PASS（要断言异常类型 + 状态未变）。
